# 유어팀 통합 홈페이지 (ur-team.com)

아임웹(마케팅)과 프레이머(유통 · 수출)로 따로 있던 두 홈페이지를 한 사이트로 합친 것입니다.
서버 · 데이터베이스 없이 HTML 파일 묶음으로 뜨므로 유지비가 들지 않습니다. 외부 라이브러리도 쓰지 않습니다.

```bash
node ur-team-site/build.mjs     # 사이트 만들기 → ur-team-site/dist/
node ur-team-site/check.mjs     # 링크 · 사진 · 예전 주소가 다 이어지는지 검사
```

`ur-team-site/` 아래를 고쳐 올리면 GitHub 이 위 두 가지를 자동으로 돌리고(`.github/workflows/ur-team-site.yml`),
완성본을 Actions 화면의 '결과물(ur-team-site)'로 올려 둡니다. 내려받아 열어 보면 됩니다.

## 폴더

| 폴더 · 파일 | 무엇 |
| --- | --- |
| `site.json` | 회사 정보(전화 · 이메일 · 카카오톡 · 상호 · 주소), 상담 신청 연결, 검색엔진 확인 코드, 예전 주소 → 새 주소 표 |
| `src/pages/` | 페이지 한 장 = 파일 하나. `marketing/hospital.html` → `/marketing/hospital/` |
| `src/posts/` | 블로그 글 한 편 = 파일 하나 |
| `src/partials/` | 모든 페이지가 같이 쓰는 칸(머리말 · 꼬리말 · 팀 소개 · 상담 안내) |
| `static/` | 사이트 맨 위에 그대로 놓는 파일(`_headers`: 보관 기간 · 글자 방식) |
| `assets/` | 디자인(CSS) · 움직임(JS) · 사진 · 영상 |
| `source/` | 옛 사이트 원본(로그인 정보 지운 것) · 공식 로고 원본 · 사진 출처 목록 |
| `tools/crops.py` | 옛 사이트 그림에서 잘라 낸 실제 화면 예시를 사이트용으로 바꾸는 도구 |

페이지에서 `<!--@ team -->` 처럼 적으면 `src/partials/team.html` 이 그 자리에 들어갑니다.

## 블로그 글 올리기

`src/posts/` 에 파일 하나를 만듭니다. 파일 이름이 주소가 됩니다(`2026-12-01-china.html` → `/blog/2026-12-01-china/`).

```html
<!-- {"title": "글 제목", "date": "2026-12-01", "category": "마케팅", "summary": "목록에 보일 한 줄", "cover": "/assets/img/…"} -->
<p>본문 첫 문단</p>
<h2>소제목</h2>
<p>…</p>
```

- 최신 날짜가 목록 맨 위에 옵니다.
- 날짜가 오늘보다 뒤인 글은 그날이 오기 전까지 사이트에 나오지 않습니다(예약 글).
- 사진은 `assets/img/` 에 넣고 `/assets/img/파일이름` 으로 적습니다.

## 상담 신청 켜기

지금은 신청서가 "온라인 접수 준비 중"으로 떠 있고, 카카오톡 · 전화로 안내합니다. 이렇게 켭니다:

1. 상인회 엔진에서 유어팀 조직의 **랜딩 편집 → 바깥 홈페이지 주소**에 `https://ur-team.com` 을 등록합니다.
   (등록 안 된 주소에서 온 신청은 엔진이 받지 않습니다.)
2. `site.json` 의 `form.endpoint` 에 `https://<엔진 주소>/lead-in/<조직 주소>` 를 적습니다.
3. 엔진에 봇 방지(Turnstile)가 켜져 있으면 `form.turnstileSiteKey` 도 적고,
   Cloudflare 에서 그 사이트 키에 `ur-team.com` 을 허용합니다.

신청서의 칸이 엔진의 어디로 들어가는지:

| 신청서 | 엔진 상담 DB |
| --- | --- |
| 업체명 · 담당자 | 이름 |
| 연락처 · 이메일 · 월 광고 예산 · 상담 신청 경로 | 같은 이름의 칸 |
| 관심 분야 · 회사 URL · 희망 채널 · 문제점 · 강점 · 문의 내용 | 상담 내용 한 칸에 `[관심 분야] …` 처럼 묶어서 |
| 광고 링크의 utm, 들어오기 전 페이지 | 유입 경로 |

## 검색 노출 (네이버 · 구글 · AI 검색)

빌드할 때 아래를 자동으로 만듭니다. 손으로 고칠 것은 `site.json` 과 각 페이지 맨 윗줄(제목 · 설명)뿐입니다.

| 만드는 것 | 무엇에 쓰나 |
| --- | --- |
| 페이지마다 구조화 데이터(JSON-LD) | 검색엔진 · AI 가 "회사 · 서비스 · 글 · 빵부스러기(홈 > 마케팅 > …)" 를 기계로 읽음 |
| `sitemap.xml` | 모든 페이지 주소 + 마지막 수정일 + 한국어 · 영어 짝. 예전 주소 이동 페이지는 뺌 |
| `robots.txt` | 모든 수집기 허용. 네이버(Yeti) · 구글 · Bing · ChatGPT · Perplexity · Claude · Gemini · Apple 을 이름으로 허용 |
| `llms.txt` · `llms-full.txt` | AI 검색이 유어팀을 바르게 소개하도록 만든 요약 · 전문. 회사 정보는 `site.json` 의 `org`, 숫자 · 고객사는 첫 화면에서 그대로 읽어 옴 |
| `/blog/rss.xml` · `/en/blog/rss.xml` | 블로그 새 글 알림(RSS). 네이버 서치어드바이저에 제출하면 새 글이 빨리 잡힘 |

- **제목 · 설명**: 페이지 맨 윗줄의 `title` · `description` 이 검색 결과에 그대로 뜹니다. 페이지끼리 겹치면 검사가 실패합니다.
  설명은 한국어 50~160자가 알맞습니다. `name` 은 빵부스러기와 서비스 이름에 쓰는 짧은 이름입니다(없으면 제목에서 만듦).
- **회사 정보**(`site.json` → `org`): 상호 · 대표자 · 사업자등록번호 · 주소 · 로고. 꼬리말과 같게 맞춰 둡니다.
- **수정일**: git 에 마지막으로 올린 날을 씁니다. 블로그 글은 글 날짜(크게 고치면 `"updated": "YYYY-MM-DD"` 를 적음).
- 검사(`check.mjs`)는 검색에 내보내는 모든 페이지에 정식 주소(canonical) 1개 · 설명 · 읽히는 구조화 데이터가 있는지,
  sitemap 이 실제 페이지와 같은지, 예전 주소 이동 페이지가 검색에서 빠져 있는지도 봅니다.

### 사이트 주인이 한 번 해야 할 일 — 검색엔진에 등록

`site.json` 의 `verification` 칸에 각 서비스가 주는 **확인 코드**를 넣으면, 모든 페이지 머리에 확인 표시가 들어갑니다.
비워 두면 아무것도 넣지 않습니다.

```json
"verification": { "google": "", "naver": "", "bing": "" }
```

1. **네이버 서치어드바이저** (searchadvisor.naver.com) → 사이트 등록 → `https://ur-team.com` →
   소유 확인 방법에서 **HTML 태그** 를 고르면 `<meta name="naver-site-verification" content="…">` 가 나옵니다.
   `content="…"` 안의 글자만 `"naver"` 에 넣고 올립니다. 확인 뒤 **요청 → 사이트맵 제출** 에 `https://ur-team.com/sitemap.xml`,
   **RSS 제출** 에 `https://ur-team.com/blog/rss.xml` 을 넣습니다.
2. **구글 서치 콘솔** (search.google.com/search-console) → 속성 추가 → **URL 접두어** `https://ur-team.com/` →
   **HTML 태그** 방법의 `content="…"` 글자를 `"google"` 에 넣습니다. 확인 뒤 **Sitemaps** 에 `sitemap.xml` 을 제출합니다.
   (도메인 전체로 등록하려면 Cloudflare DNS 에 TXT 기록을 넣는 방법도 있습니다. 그때는 이 칸이 필요 없습니다.)
3. **Bing 웹마스터 도구** (bing.com/webmasters) — ChatGPT 검색 · Copilot 이 Bing 색인을 씁니다.
   구글 서치 콘솔에서 가져오기를 누르면 따로 확인 없이 끝납니다. 직접 하려면 `msvalidate.01` 코드를 `"bing"` 에 넣습니다.

## ur-team.com 에 올리기

`dist/` 폴더가 완성본입니다. 정적 파일을 올릴 수 있는 곳이면 어디든 됩니다.
Cloudflare Pages 를 쓰면 `dist/_redirects` 를 읽어 예전 주소(`/hospital`, `/product-3`, `/kr/export` …)를
새 주소로 영구 이동(301)시킵니다. 다른 곳에 올려도 예전 주소마다 이동 페이지가 들어 있어서 링크가 끊기지 않습니다.

- 빌드 명령: `node ur-team-site/build.mjs` · 결과 폴더: `ur-team-site/dist`
- 도메인을 옮기기 전에 프레이머 · 아임웹 구독을 먼저 끊지 마세요. 새 사이트가 뜬 것을 확인한 뒤에 끊습니다.

## 알아둘 한계

- 마케팅 상품 8개 페이지는 아임웹 설명 그림 속 글을 옮겨 적어 새로 만들었습니다. 그림으로 남은 것은 실제 화면 예시(검색 결과 등)뿐입니다.
- 회사소개서 다운로드 버튼은 PDF 파일을 받으면 붙입니다.
- 영어판(`/en/…`)은 한국어 페이지와 짝을 이룹니다. 한쪽 언어에만 있는 글(지금은 블로그 글)은 그 언어로만 검색에 나갑니다.
- 검색 등록 직후에는 노출까지 며칠~몇 주가 걸립니다. 구조화 데이터를 넣었다고 검색 결과 모양(별점 · 빵부스러기 등)이 꼭 바뀌는 것은 아닙니다.
