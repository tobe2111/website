# 서초구 상인회 플랫폼 — Cloudflare 버전 (Workers + D1 + R2)

기존 Node 서버 버전(저장소 루트)을 **Cloudflare 무료 티어**에서 돌도록 이식한 버전입니다.
깃허브 push → 자동 배포, HTTPS 자동, **영구 무료** 운영이 가능합니다.

- **배포 방법**: [DEPLOY-cloudflare.md](./DEPLOY-cloudflare.md) 참고
  - **거의 클릭만**: 깃허브 저장소를 Cloudflare 대시보드에서 Import → 접속하면 `/setup` 설치 화면.
    표 생성·시크릿(세션/서명 키)·초기 계정이 **전부 자동**(첫 실행 시 스스로 준비).
- **로직 테스트**: `node --experimental-sqlite --test cloudflare/test/*.test.js` (34건)
  - wrangler 없이도 D1/R2/ASSETS 를 에뮬레이션해 워커 로직을 검증합니다.

## 기능 (Node 버전과 동일)
상인회 소개·홈, 가입 점포 안내·상세, 점포 지도(네이버), 공지(카테고리·검색),
행사, 회원 게시판(다중 이미지·검색·수정), 회원가입·대시보드(사진 R2·영상 임베드),
관리자(승인·공지·행사·브랜딩·회원 CSV), 슈퍼관리자(멀티테넌트 사이트 복제),
전자서명(Ed25519 순차·기한·공개 검증).

## 조직 유형(kind) — 같은 엔진, 여러 제품

한 워커가 여러 제품을 함께 굽습니다. 조직마다 `associations.kind` 하나로 갈립니다.

| kind | 공개 화면 | 관리자 화면 | 제품 소개 페이지 |
| --- | --- | --- | --- |
| `merchant` | 상인회 홈(점포·지도·공지·게시판) | 승인·공지·회비·홈 구성 | `/` |
| `esign` | 계약 창구(서명 입구·진위확인) | 계약서·서식·담당자 | `/esign` |
| `franchise` | **모집 랜딩 한 장** | **랜딩 편집 + 상담 DB** | `/homepage` |

**정의는 `src/kinds.js` 한 곳에 있습니다.** 라벨·메뉴 모양·콘솔 패널 스위치·기본 문구가 전부
거기 있고, 나머지 파일은 그 표를 읽기만 합니다. 새 제품을 더할 때 열 군데를 고칠 필요가 없습니다.

### 업종 프리셋 — 화면은 같고 말만 다른 제품

모집형(`franchise`)은 **업종 프리셋**을 함께 가집니다(`associations.preset`).
구조는 그대로 두고 문구와 용어만 갈아 끼웁니다.

| preset | 쓰는 곳 | 상담 용어 |
| --- | --- | --- |
| `franchise` | 프랜차이즈 가맹점 모집 | 가맹 상담 |
| `academy` | 학원·교습소 | 입학 상담 |
| `fitness` | 헬스장·필라테스 | 등록 상담 |
| `clinic` | 병원·클리닉 | 진료 상담 |
| `realestate` | 분양·부동산 | 분양 상담 |

프리셋을 추가하는 데는 항목 하나면 됩니다(안 채운 문구는 대표 프리셋에서 자동으로 빌려 옵니다).
→ **[docs/새-제품-유형-추가하기.md](../docs/새-제품-유형-추가하기.md)**

### 사이트 찍어 내기

슈퍼 콘솔(`/super`)에서 두 가지로 만듭니다.

- **새로 만들기** — 유형·업종을 고르면 그 업종 문구가 채워진 채로 열립니다(모집형은 랜딩이 발행된 상태).
- **기존 사이트 복제** — 잘 만든 사이트를 본으로 찍어 냅니다.
  - 따라오는 것: 유형·업종·대표색·홈/랜딩 구성·캠페인 사본
  - 따라오지 **않는** 것: 회원·점포·상담 신청·계약 (남의 실제 데이터는 절대 복사하지 않습니다)

### 프랜차이즈 가맹점 모집 랜딩 (`kind=franchise`)

광고를 타고 들어온 사람의 **연락처를 받는 것**이 유일한 목표인 한 장짜리 화면입니다.

- **랜딩 구성** (`src/franchise.js`) — 히어로 · 흐르는 띠 · 브랜드 소개 · 창업 강점 · 점주 후기 ·
  메뉴 라인업 · 가맹 절차 · 가맹 비용(가리기 가능) · **상담 신청 폼** · 매장 안내 · FAQ · 공지 · 마무리 배너.
  섹션마다 켜기/끄기·순서·문구를 관리자가 직접 고칩니다(`/t/:slug/admin/landing`).
  반복 항목은 **한 줄에 하나, 칸은 `|`** 로 입력합니다 — 예: `가맹비 | 1,000만원 | 부가세 별도`.
- **초안 → 발행** — 저장은 초안까지만. 손님에게는 발행본이 보이고, 관리자는
  `/admin/landing/preview` 로 초안을 먼저 확인합니다. 고치는 동안 공사판이 노출되지 않습니다.
- **사진 보관함** — 관리자가 사진을 올리면 `/media/…` 주소가 생기고, 그 주소를 섹션에 붙여 넣습니다
  (히어로·브랜드 사진 칸은 파일 선택만으로 바로 채워집니다). 외부 `https://` 주소도 그대로 씁니다.
- **캠페인별 사본** — `/t/:slug/l/:campaign` 으로 열리는 랜딩 사본. 광고 소재마다 다른 문구를 쓰고
  **방문·신청·전환율을 사본별로 비교**합니다. 사본은 `robots.txt` 에서 색인 제외(중복 콘텐츠 방지).
  사본을 지우면 그 방문 기록은 **'지워진 것' 칸으로 옮깁니다** — 같은 이름으로 다시 만들었을 때
  작년 숫자가 올해 성과로 붙으면 안 되고, 그렇다고 지워 버리면 그 사본으로 들어온 상담은 남은 채
  분모만 줄어 전환율이 실제보다 좋아 보이기 때문입니다.
- **고정 하단 바** — 랜딩뿐 아니라 매장·공지 등 손님 화면 전체에서 전화·상담 신청이 손끝에 있습니다
  (관리자 콘솔에는 붙지 않습니다).
- **상담 DB** (`leads` 표) — 성함·연락처·희망 지역·창업 예산·유입 경로·문의 내용, 그리고
  **광고 출처**(`utm_source/medium/campaign` · referrer · 사본)까지 자동 기록.
  `/t/:slug/admin/leads` 에서 상태(신규·연락 완료·상담/방문·계약·보류)·메모·CSV·삭제와
  **30일 전환율 · 광고 출처별 집계 · 랜딩별 성과**를 봅니다(50건씩 쪽 나눔).
- **전화도 전환으로 셉니다** — 모바일에서는 폼을 채우기보다 그냥 거는 사람이 많아, 전화를 빼고 보면
  전환율이 실제보다 낮게 나옵니다. 하단 바의 통화 버튼 클릭을 `sendBeacon` 으로 집계해
  **전환율 = (신청 + 전화) ÷ 방문** 으로 봅니다. 집계가 실패해도 전화 연결은 그대로 됩니다.
  방문 100회 미만인 사본에는 **표본 부족**을 표시합니다 — 20회로 나온 전환율을 믿고
  광고비를 옮기면 그게 가장 비싼 실수라서입니다.
- **업종별 추가 질문** — 고정 칸(성함·연락처·지역·예산) 외에 필요한 것을 관리자가 정의합니다
  (`질문 | 종류 | 선택지`). 답은 `leads.extra` 에 담기고 상담 DB·CSV 에 함께 나옵니다.
  무엇을 물었는지는 **발행된 랜딩**이 정합니다 — 폼이 보낸 라벨은 신뢰하지 않습니다.
- **주간 리포트** — 매주 대표 메일로 지난 7일 요약(신청·방문·전환율·계약·미처리 + 광고 출처).
  미처리가 쌓여 있으면 신청이 없어도 보냅니다. 그게 진짜 위험 신호라서입니다.
- **알림** — 새 상담이 오면 담당자에게 알림톡(`lead_new`)과 메일, 신청자에게 접수 확인
  알림톡(`lead_ack`). 알림톡 설정이 없어도 접수 자체는 그대로 저장됩니다.
  발송은 **조직당 하루 200건**으로 묶여 있습니다 — 이 발송의 방아쇠는 '누구나 보낼 수 있는
  공개 폼'이라, 상한이 없으면 남의 번호로 문자를 쏘고 조직의 크레딧을 태우는 통로가 됩니다.
  상한을 넘으면 발송만 멈추고 접수는 계속 받습니다.
- **상담 → 계약** — 상담 건의 `계약서 만들기` 를 누르면 서식 선택 → 문서 생성 → 외부 서명자 폼까지
  신청자 정보가 따라가, 이름·번호를 다시 옮겨 적지 않습니다.
- **사진은 올릴 때 브라우저가 줄입니다** — 관리자는 폰으로 찍은 사진(4032px·2MB 안팎)을
  그대로 고릅니다. 그게 히어로 배경이 되면 광고로 들어온 사람 **전부**가 그 무게를 집니다.
  브라우저에서 긴 변 1600px·품질 82%로 줄여 보냅니다(EXIF 회전 반영, 실패하면 원본 그대로).
  실측: **LCP 11.40초 → 2.01초** (모바일 4G·CPU 4배 감속, 5회 중앙값).
- **첫 화면을 먼저 받습니다** — 히어로 사진은 CSS `background-image` 라 브라우저의 preload
  스캐너가 발견하지 못하고, CSS 파싱·레이아웃을 기다린 뒤에야 받기 시작합니다. 광고로 들어온
  사람에게는 그 지연이 곧 이탈이라 `<link rel="preload" as="image" fetchpriority="high">` 로
  HTML 과 동시에 받게 합니다.
- **입력값을 잃지 않습니다** — 동의 미체크·연락처 오타·봇 방지 실패로 폼이 되돌아올 때,
  쓰던 값이 그대로 남아 있습니다. 문의 내용을 길게 쓴 사람일수록 손해가 크고 그런 사람이
  가장 진지한 신청자입니다. 값은 **브라우저 안에만** 둡니다 — URL 로 되돌리면 이름·전화번호가
  서버 로그와 브라우저 기록에 남습니다. 개인정보 **동의 체크는 복원하지 않고**(본인이 직접
  체크해야 동의입니다), 접수되면 보관분을 지웁니다.
- **쓰레기 차단** — 봇 방지(Turnstile) · 허니팟 · 같은 번호 10분 내 재전송 차단(하이픈 무시) ·
  IP 당 제출 제한(15분 20건). 방문 수는 크롤러(UA)와 1분 내 재조회를 빼고 셉니다 —
  분모가 부풀면 전환율이 거짓말을 하고 광고 판단이 틀어집니다.
- **개인정보** — 수집 항목을 최소로 두고, **처리가 끝난 건(계약·보류)은 보관 기간이 지나면 매일
  크론이 자동 파기**합니다(기본 365일, 조직별 설정). 진행 중인 건은 지우지 않으며, 삭제 시
  감사 로그에도 이름·번호를 남기지 않습니다.

성능을 재려면 (`scripts/measure.mjs`) — 감이 아니라 숫자로 봅니다. 모바일 4G + CPU 4배 감속에서
LCP·FCP·CLS·전송량을 5회 중앙값으로 재고, 히어로 사진 유무·크기·preload 유무를 비교합니다.
**측정 서버는 반드시 brotli 를 켭니다** — 압축 없이 재면 CSS 가 실제(26KB)의 다섯 배로 보여
있지도 않은 문제를 고치게 됩니다.

```bash
node --experimental-sqlite scripts/measure.mjs      # 성능 실측
node --experimental-sqlite scripts/shoot.mjs 폴더   # 화면 사진 (영업 자료·눈 검사용)
```

화면을 눈으로 확인하려면:

```bash
node --experimental-sqlite scripts/preview-franchise.mjs public/__x.html landing  # 손님이 보는 랜딩
node --experimental-sqlite scripts/preview-franchise.mjs public/__x.html leads    # 상담 DB 콘솔
node --experimental-sqlite scripts/preview-franchise.mjs public/__x.html editor   # 랜딩 편집기
# 브라우저로 public/__x.html 열기 (확인 후 삭제)
```

## 구조
```
(저장소 최상단)
  wrangler.toml        # Workers/D1/R2/ASSETS 바인딩 — 최상단에 두어야 깃허브 자동 배포가
                       #   빌드 루트 설정(/ 또는 cloudflare)과 무관하게 동작한다
cloudflare/
  schema.sql           # D1 스키마
  src/
    index.js           # fetch 라우터 + 테넌트/인증/CSRF/보안헤더
    db.js              # D1 비동기 데이터 레이어
    kinds.js           # ★ 제품 유형·업종 프리셋 레지스트리 (새 제품은 여기부터)
    homeLayout.js      # 상인회 홈 섹션 카탈로그·렌더러
    franchise.js       # 프랜차이즈 랜딩 섹션 카탈로그·렌더러 (가맹 상담 폼 포함)
    crypto.js          # Web Crypto (PBKDF2·HMAC)
    auth.js            # 세션·CSRF
    esign.js           # Ed25519 전자서명
    storage.js         # R2
    pages.js / api.js  # 페이지(GET) / 폼(POST) 핸들러
    render.js media-render.js embed.js util.js http.js
  scripts/             # 서명키·시드 SQL 생성기
  test/                # D1/R2 에뮬레이터 + node:test
  public/              # 정적 자산(css/js)
```

ffmpeg 가 없는 환경이라 **사진 썸네일은 원본을 사용**합니다(영상은 임베드라 무관).
그 외 기능·보안은 Node 버전과 동일합니다.
