# 유어딜 API 에 부탁드릴 것 (상인회 홈페이지 연동)

상인회 홈페이지의 **우리 골목 이용권** 섹션이 유어딜 공개 API 를 부릅니다.
지금도 동작하지만 두 가지가 아쉽고, 하나는 사고가 날 수 있는 자리입니다.

측정한 날: **2026-09-05** · 대상: `https://live.ur-team.com`

---

## 1. (중요) 거르개가 조용히 무시됩니다

`seller_id` 에 숫자가 아닌 값이 들어오면 오류를 내는 대신 **거르지 않은 전체 목록**을 돌려줍니다.

| 요청 | 결과 |
| --- | --- |
| `?deal_only=1&seller_id=1&limit=100` | 0건 (정상 — 그 가게에 이용권이 없음) |
| `?deal_only=1&seller_id=1,2&limit=100` | **100건** — 거르개 무시, 전체 반환 |
| `?deal_only=1&seller_ids=1,2&limit=100` | **100건** — 없는 칸이라 무시, 전체 반환 |

부르는 쪽에서 실수 한 번이면 **다른 지역 가게의 상품이 우리 골목 상품인 것처럼 화면에 걸립니다.**
저희 쪽은 두 겹으로 막아 뒀지만(주소를 만들기 전 정수 검사 + 돌아온 줄의 `seller_id` 재확인),
유어딜 쪽에서도 **알 수 없는 값이면 400 을 주시거나 빈 목록을 주시는 편**이 안전합니다.

## 2. 여러 가게를 한 번에 부르고 싶습니다

지금은 가게 수만큼 호출합니다. 상인회 한 곳에 가게가 12곳이면 12번입니다.
(저희 쪽에서 10분 캐시 · 2.5초 제한 · 가게당 3개 · 최대 12곳으로 묶어 두긴 했습니다.)

부탁:

```
GET /api/products?deal_only=1&seller_id=128,300,411&limit=36
```

또는 `seller_id` 를 여러 번 받아 주셔도 됩니다(`seller_id=128&seller_id=300`).
지금은 두 방식 모두 전체 목록이 돌아옵니다.

## 3. 지역 단위 조회가 있으면 더 좋습니다

```
GET /api/products?deal_only=1&region=서초구&limit=36
```

상인회는 "우리 동네 가게" 단위로 생각합니다. 가게 번호를 하나씩 적어 두는 지금 방식은
가게가 늘 때마다 상인회 총무가 손으로 번호를 옮겨 적어야 합니다.

## 4. 참고 — 지금은 가게 소유 이용권이 하나도 없습니다

`deal_only=1` 로 받은 상품 500건이 **전부 `seller_id: null`** 이었습니다(플랫폼/기프티쇼 상품).
그래서 상인회 홈의 이용권 자리는 지금 어느 상인회에서도 비어 있고,
"우리 가게 이용권 만들어서 홍보하기" 안내 카드만 뜹니다 — 의도한 동작입니다.

가게가 직접 올린 이용권이 생기면 그 상품의 `seller_id` 가 채워져야 저희 화면에 걸립니다.
