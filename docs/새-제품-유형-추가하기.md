# 새 제품 유형 · 새 업종 추가하기

이 플랫폼은 워커 하나가 여러 제품을 함께 굽습니다. 지금은 세 가지입니다.

| 유형(`kind`) | 손님이 보는 것 | 관리자가 하는 일 |
| --- | --- | --- |
| `merchant` | 상인회 홈(점포·지도·공지·게시판) | 승인·공지·회비·홈 구성 |
| `esign` | 계약 창구(서명 입구·진위확인) | 계약서·서식·담당자 |
| `franchise` | 모집 랜딩 한 장(상담 신청) | 랜딩 편집·상담 DB |

새로 만들 때 고를 길은 **두 가지**입니다. 대부분은 ①로 충분합니다.

---

## ① 업종만 다른 모집 사이트 → 프리셋 한 벌 (5분)

학원·헬스장·병원·분양처럼 **화면 구조는 같고 말만 다른** 경우입니다.
`cloudflare/src/kinds.js` 의 `PRESETS` 에 항목 하나를 더하면 끝입니다.

```js
// cloudflare/src/kinds.js
export const PRESETS = {
  // …기존 프리셋…
  petshop: {
    label: "애견 유치원 · 호텔",                       // 슈퍼 콘솔 선택지에 뜨는 이름
    terms: { consult: "입소 상담", unit: "지점", store: "지점",
             applicant: "보호자", cost: "이용 요금", process: "입소 절차" },
    tagline: "하루를 맡겨도 마음이 놓이게",
    hero: { eyebrow: "신규 원생 모집", title: "맡기는 동안\n불안하지 않게", highlight: "불안하지",
            subtitle: "{name}는 CCTV 공개와 일일 리포트로 하루를 그대로 보여드립니다.",
            ctaLabel: "입소 상담 신청하기", note: "상담은 무료입니다." },
    ticker: "24시간 CCTV 공개\n일일 알림장\n소형견·대형견 분리\n픽업 서비스",
  },
};
```

- `{name}` 은 조직 이름으로 치환됩니다.
- **안 쓴 항목은 대표 프리셋(프랜차이즈)에서 자동으로 빌려 옵니다.** 위 예시처럼 히어로와
  띠만 써도 강점·절차·FAQ·비용 문구가 채워진 채로 화면이 섭니다. 스무 개 문단을 다 쓰게
  만들면 아무도 업종을 추가하지 않기 때문입니다.
- `terms` 는 메뉴·고정 하단 바·상담 폼·관리자 화면 문구에 그대로 쓰입니다
  ("가맹 상담" ↔ "입학 상담" ↔ "입소 상담").

**끝입니다.** 슈퍼 콘솔의 업종 선택지, 새 조직의 기본 랜딩, 상담 폼의 칸 이름이 전부 따라옵니다.
확인은 이렇게:

```bash
node --experimental-sqlite --test cloudflare/test/kinds.test.js   # 프리셋 완결성 자동 검사
```

`kinds.test.js` 의 "업종 프리셋" 테스트가 **모든 프리셋을 순회**하므로, 빠뜨린 항목이 있으면
새 업종을 추가한 순간 테스트가 알려 줍니다.

## ② 화면 구조 자체가 다른 새 제품 → 유형 한 줄 (반나절)

예약 시스템, 채용 사이트처럼 **화면 구성이 다른** 경우입니다.

### 1. 레지스트리에 유형을 더합니다

```js
// cloudflare/src/kinds.js
export const KINDS = {
  // …기존 유형…
  booking: {
    id: "booking", label: "예약", badge: "badge-info", orgWord: "매장",
    createHint: "예약 접수 + 일정 관리",
    tagline: "기다리지 않게 하겠습니다",
    home: "booking",          // 손님 홈을 그리는 방식 (pages.js home() 분기 키)
    nav: "booking",           // 상단 메뉴 모양 (render.js navHtml 분기 키)
    selfRegister: false,      // 손님이 스스로 가입할 수 있는가
    usesLanding: false,       // 랜딩 편집기·고정 하단 바를 쓰는가
    console: { businesses: false, products: false, dues: false, homeLayout: false,
               content: true, polls: false, invite: false, proxyAdd: false,
               staff: true, landing: false, leads: true },
    dashTitle: "예약 관리", siteWord: "예약 창구",
  },
};
```

`console` 스위치가 관리자 콘솔에서 어떤 패널을 띄울지 정합니다. **여기 있는 값만 보고
화면이 조립되므로, 콘솔 쪽은 더 손대지 않아도 됩니다.**

### 2. 홈 렌더러를 붙입니다

`cloudflare/src/pages.js` 의 `home()` 은 레지스트리의 `home` 값으로 갈라집니다.

```js
const home = kindOf(assoc).home;
if (home === "esign") return esignHome(ctx);
if (home === "landing") return franchiseHome(ctx);
if (home === "booking") return bookingHome(ctx);   // ← 한 줄
```

메뉴가 다르면 `render.js` 의 `navHtml()` 에 `K.nav === "booking"` 갈래를 하나 더합니다.

### 3. 필요하면 표를 더합니다

`cloudflare/src/schema.js` 의 `SCHEMA_SQL` 에 표를 쓰고, `migrateColumns()` 끝에
`CREATE TABLE IF NOT EXISTS …` 를 더한 뒤 `SCHEMA_VERSION` 을 +1 합니다.
그 다음 `schema.sql` 을 다시 만듭니다.

```bash
cd cloudflare
node -e "import('./src/schema.js').then(m=>require('fs').writeFileSync('schema.sql', m.SCHEMA_SQL.replace(/^\n/,'')))"
```

> 새 표를 만들었다면 **주간 백업 목록**(`src/scheduled.js` 의 `TABLES`)에도 넣으세요.
> 넣지 않으면 그 데이터만 백업에서 조용히 빠집니다.

## 사이트를 계속 찍어 내기

유형과 업종이 정해졌으면, 실제 고객사 사이트는 슈퍼 콘솔(`/super`)에서 두 가지 방법으로 만듭니다.

1. **새로 만들기** — 유형·업종을 고르면 그 업종의 기본 문구가 채워진 채로 열립니다.
2. **기존 사이트 복제해서 만들기** — 잘 만들어 둔 사이트를 본으로 찍어 냅니다.
   - 따라오는 것: 유형·업종·대표색·홈/랜딩 화면 구성·캠페인 사본
   - 따라오지 **않는** 것: 회원·점포·상담 신청·계약 — 남의 실제 데이터는 절대 복사하지 않습니다

복제본은 원본과 완전히 분리된 사이트입니다. 이후 편집은 각자 알아서 합니다.

## 원칙 (이걸 지켜야 계속 늘릴 수 있습니다)

- **분기는 레지스트리에만.** 코드 여기저기에 `kind === "..."` 를 새로 쓰지 마세요.
  판단이 필요하면 `kinds.js` 에 스위치를 하나 더하고 그걸 읽습니다.
- **업종 문구는 프리셋에만.** 화면 코드에 "가맹" 같은 업종 단어를 박지 말고 `terms` 를 씁니다.
- **기본값은 거짓말하지 않게.** 확인하지 않은 숫자(가맹점 수, 매출)를 기본 문구에 넣지 마세요.
  한 번 박히면 그대로 광고에 실립니다.
- **개인정보는 복사·백업·삭제를 함께 생각.** 새 표에 연락처가 들어가면 백업 목록과
  파기 크론(`runLeadPurge` 참고)도 같이 챙깁니다.
